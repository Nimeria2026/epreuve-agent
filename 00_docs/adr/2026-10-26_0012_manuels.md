# ADR 0012 : un dossier pour les manuels

Date : 2026-10-26
Statut : accepté

## Problème rencontré

Le 2026-10-26, Alexandre demande trois documentations compartimentées rubrique par rubrique : le
manuel de fonctionnement et d'utilisation de l'Épreuve d'agent, le guide remis à l'entreprise avec
son rapport, l'argumentaire pour répondre aux entreprises (JOURNAL, entrée 317 ; cadrage
`00_docs/sources/2026-10-26_cadrage_manuels.md`). Le plan du dépôt n'a pas de place pour elles :
`00_docs/sources/` garde des notes datées, qui ne se réécrivent pas après coup, alors qu'un manuel
vit et se corrige à chaque commande changée ; `00_docs/protocole/` est figé par version ;
`ATELIER.md` et `AGENTS.md` sont écrits pour une IA, pas pour un lecteur humain qui découvre le
banc.

## Décision

`00_docs/manuels/`, avec un sommaire (`README.md`) et un dossier par documentation :
`utilisation/`, `entreprises/`, `argumentaire/`, chacun avec son sommaire et une page par
rubrique, numérotée dans l'ordre de lecture. Les manuels renvoient à `ATELIER.md`, à `AGENTS.md`,
aux README et aux cadrages pour le détail, sans les recopier ; un test vérifie que les commandes
`make` qu'ils citent existent. Aucun ne sort dans l'export public, qui procède par liste de
dossiers inclus : le guide pour l'entreprise n'y entrera que si Alexandre décide de le publier.

## Alternatives écartées

- Les ranger dans `00_docs/sources/` : une note datée ne se corrige pas, et le manuel serait faux
  à la première commande renommée.
- Des fichiers à la racine : la racine ne porte que les portes d'entrée et le pilotage, et trois
  documentations de plusieurs pages l'encombreraient.
- Des documents hors du dépôt (Claude Docs, un traitement de texte) : l'abonnement à Claude se
  termine, et opencode ne les modifierait pas ; hors du dépôt, ils ne se versionnent pas.

## Conséquences

`arborescence.toml` passe en version 12 : `manuels/` entre dans les entrées de la zone `00_docs`.
`00_docs/README.md` présente le dossier. Rien ne change dans le code ni dans l'export public.
