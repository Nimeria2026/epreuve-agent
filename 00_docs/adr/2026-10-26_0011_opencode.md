# ADR 0011 : les règles de l'atelier pour opencode

Date : 2026-10-26
Statut : accepté

## Problème rencontré

Le 2026-10-26, Alexandre veut pouvoir mesurer un nouveau modèle depuis opencode, avec un autre
modèle que Claude (JOURNAL, entrée 303). La documentation d'opencode, lue le même jour, dit qu'il
lit `AGENTS.md` de lui-même, mais pas les fichiers que celui-ci cite : `ATELIER.md`, qui porte les
règles de l'atelier, ne se lit que si le modèle obéit à la première ligne d'`AGENTS.md`. Rien
n'empêche non plus ce modèle d'ouvrir `07_taches/prive/`, `.env` ou un journal du candidat ; les
ouvrir suffit à les envoyer chez son fournisseur, ce que les tâches cachées doivent éviter
(`AGENTS.md`, « Les tâches cachées »).

## Décision

`opencode.json` à la racine, la configuration de projet d'opencode :

- `instructions` charge `ATELIER.md` à chaque séance ;
- `permission.read` refuse `07_taches/prive/`, `99_local/seance_cachees/`, `.env` et les
  `*_candidat.log`, et demande l'accord d'Alexandre avant d'ouvrir un fichier de `99_local/runs/`,
  `runs_tau2/` ou `importes/` ;
- `permission.edit` refuse d'écrire dans ces dossiers, dans `.env` et dans une publication de
  `08_publications/` ;
- `permission.bash` refuse les commandes qui citent ces chemins ou `.env`, `git add -A`,
  `git add .`, `git commit -a`, `git worktree prune` et `--no-verify`, et demande l'accord avant
  `rm`, `git rm` et `git push`.

Les règles d'opencode s'appliquent dans l'ordre, la dernière qui correspond l'emporte : chaque
liste commence par le cas général, les refus viennent en dernier. Pour `read` et `edit`, le cas
général `"*": "allow"` reprend la valeur par défaut que donne la documentation.

Le fichier ne sort pas dans l'export public, qui n'a pas d'`ATELIER.md`.

## Alternatives écartées

- La configuration globale d'opencode, dans le dossier personnel d'Alexandre : elle vaudrait pour
  tous ses projets, et ne suivrait ni l'atelier ni ses postes de mesure.
- La seule consigne d'`AGENTS.md` : elle dépend du modèle, quand un fichier de permissions ne
  dépend que d'opencode.

## Conséquences

- `arborescence.toml` passe en version 11 et cite l'ADR 0011 : la racine permet `opencode.json`.
- Les postes de mesure, copies de l'atelier, ont la même configuration.
- Limites, d'après la documentation : `grep` et `glob` d'opencode se règlent sur le motif cherché et
  non sur le chemin, et ce fichier ne les restreint pas ; les règles de `bash` portent sur le texte
  des commandes, qu'un détour peut éviter. C'est un garde-fou : la règle reste celle d'`AGENTS.md`
  et d'`ATELIER.md`.
- `02_ease/tests/test_opencode.py` vérifie que le fichier se lit et garde ces refus.
